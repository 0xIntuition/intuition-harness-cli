# ENG-11216 Validation

## Investigation

- Confirmed the intended lifecycle is one hidden `listen-worker` process per issue run. The worker owns the multi-turn loop in `src/listen/worker.rs`; turn transitions persist new phase/turn metadata but should keep the same worker PID.
- The ENG-11212 incident produced multiple live `intu listen-worker` processes and Codex children for the same issue workspace. The follow-up Linear comment also notes the dashboard appeared to cycle through PIDs `16690`, `57417`, and `7253` during one `intu agents listen --team ENG --project Inbox & Notifications` run.
- Confirmed there was no workspace-scoped lease before this change. The project-level `active-listener.lock.json` only prevented duplicate listener processes for one project store; it did not prevent retry, stale recovery, execute, or another project-store path from launching a second worker against the same ticket workspace.
- Confirmed hidden worker children were spawned and then dropped by the launcher. A finished child could remain unreaped long enough to confuse PID-based reconciliation; `pid_is_running` also treated zombie PIDs as live because it only checked `ps -p`.
- Confirmed the added artifact bug: validation handoff artifacts could become self-invalidating when they committed volatile fields such as latest SHA, PR head, timestamps, run IDs, or turn counts. The ENG-11212 / PR #397 run accumulated repeated docs-only checkpoint commits before manual cleanup squashed the branch back to one implementation commit.
- After PR publication, GitHub Actions `quality` failed under stable Rust/Clippy 1.95 on mechanical lints that local Rust/Clippy 1.94 did not emit. The branch includes a follow-up lint-only compatibility commit for those CI-toolchain findings.

## Change Summary

- Added a workspace-local `.metastack/listen-worker.lock.json` lease acquired by the worker before the turn loop.
- Launch paths now refuse a live lease owner, wait for the child to acquire the lease before reporting the PID active, and reap the child after exit.
- `pid_is_running` now treats PID `0` and zombie `ps` states as not running.
- Per-issue logs now include worker lifecycle records and per-turn agent-child PID lifecycle records.
- Validation artifact diffs that only refresh volatile handoff/checkpoint fields are classified separately and do not count as implementation progress.
- Applied CI-toolchain Clippy compatibility cleanups in event-handler and sorting code paths so the branch passes the GitHub workflow's stable toolchain.
- Updated the injected workflow contract, CLI docs, and listener docs to describe the one-worker lease and to discourage validation-artifact-only volatile commits.

## Manual Smoke Test

Use a low-risk demo issue or throwaway project:

1. Start `intu agents listen --team ENG --project "<demo project>"`.
2. Let a claimed issue enter turn 1 and note the dashboard PID.
3. Attempt a second launch against the same workspace through retry or execute while the first worker is still running.
4. Confirm the second launch fails before mutating the workspace with a live lease-owner message.
5. Confirm `ps` shows at most one live `intu listen-worker ... --workspace <same path> --issue <same issue>`.
6. Confirm the issue log contains `listen-worker lifecycle event=spawn`, `event=lease_acquired`, `event=exit`, and `agent-child lifecycle` lines.
