# ENG-10793 Validation Evidence

## Summary

Repo-level reviewer evidence for ENG-10793: listen turn-one artifacts are now
complementary instead of repetitive. Generated briefs drop the full
`## Linear Description` and placeholder-heavy `_Missing ..._` sections, keep
ticket identity and goal, point to repo-local codebase markdown paths instead
of inlining those files, and preserve verbatim inline `Validation`, `Test
Plan`, and `Acceptance Criteria` sections when present. Turn-one prompts now
render live execution metadata plus one compact description summary, prepend a
deterministic read-first attachment summary, keep discussion context as a
bounded newest-first summary, and avoid duplicating the same full issue body
across both the brief and the prompt. First-turn instructions now render as
exactly three logical blocks, while turn-two-and-beyond continuation prompts
remain unchanged.

The ticket also adds deterministic regression guardrails across the required
fixture classes: `small-happy-path`, `large-narrative`, `validation-heavy`,
`attachment-heavy`, and `discussion-heavy`. Those fixtures now back byte-budget
assertions for briefs, turn-one prompts, and first-turn instructions.

A final checkpoint follow-up also tightens discussion-summary budgeting so
reviewer labels count inside the total character cap instead of being excluded
from the budget math. A dedicated regression test now covers that edge case.

Because the previous listen turn timed out before the long-running repo gate
completed, this continuation reran `make quality` to a clean exit so review
handoff does not depend on partial validation output.
