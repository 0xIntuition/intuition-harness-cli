# ENG-10749 Validation Evidence

## Summary

Repo-level reviewer evidence for ENG-10749: listen session merging now rejects
PR #95-style stale daemon overwrites of protected worker-owned state, structured
verification requires a passing `quality` workflow for the exact active PR HEAD
SHA, and structured review prompts explicitly call out cross-actor state
ownership plus the highest-risk listen modules. Review-handoff flow was also
hardened so final verification resolves or creates the draft branch PR before
applying the exact-SHA verification gate. A follow-up review pass also fixed the
remaining merge hole where newer daemon timeout metadata could be discarded when
worker-owned state regressed in the same snapshot.

## Acceptance Criteria Mapping

- `tests/listen.rs` now reproduces the stale-overwrite shape and verifies the
  monotonic contract around blocked metadata, canonical metadata,
  `turn_history`, and `latest_resume_handle`.
- `src/listen/mod.rs` rejects stale daemon replacement when protected fields
  regress, preserves richer worker state across session reconciliation, and
  still adopts newer daemon timeout metadata instead of dropping it.
- `src/github_pr.rs` and `src/listen/worker.rs` resolve the active branch PR,
  current `headRefOid`, and `quality` workflow runs for that exact SHA before
  verification can report success.
- `src/listen/worker.rs` now blocks verification with remediation for missing,
  pending, failed, stale, or unresolvable workflow and PR metadata.
- Structured review prompt hardening is implemented in
  `src/listen/worker.rs` and anchored by the prompt probe exported through
  `src/lib.rs` plus listen integration coverage in `tests/listen.rs`.
- Reviewer-facing docs were updated in `README.md` and `WORKFLOW.md` to reflect
  the exact-SHA gate and its fail-closed behavior.

## Notes

- A continuation-turn review pass found that the merge ranking still rejected a
  newer daemon snapshot wholesale when worker-owned fields regressed, which
  could drop the latest `last_timeout` record. `src/listen/mod.rs` now merges
  protected worker-owned fields first and then evaluates replacement.
- Several stale `cargo test` processes from earlier timed-out turns were still
  holding local Cargo locks. Clearing those stale processes removed the timeout
  root cause before the final `make quality` rerun.
- Timeout-path proofs were rerun explicitly after the continuation-turn timeout
  interruptions so review handoff does not rely on an inferred timeout state.
