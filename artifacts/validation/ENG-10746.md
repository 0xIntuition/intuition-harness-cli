# ENG-10746 Validation Evidence

## Summary

Repo-level reviewer evidence for ENG-10746: listen-store JSON persistence now
uses same-directory temp files plus atomic persist semantics, startup-critical
listen metadata recovers deterministically from sibling artifacts when the
primary JSON is corrupt, and active-listener lock acquisition and cleanup now
distinguish corrupt/stale orphaned locks from valid live locks without deleting
replacement lock files. A follow-up verification repair also ensures built-in
Claude listen turns seed canonical provider/model/reasoning before running
state writes and before blocked-session persistence, so the final stored
session and detail artifacts do not regress to null metadata on either
successful or failed execution turns.

## Acceptance Criteria Mapping

- `src/session_runtime.rs` now writes JSON through same-directory temp files,
  `sync_all()`, and atomic `persist` / `persist_noclobber`, preserving overwrite
  and exclusive-create semantics without exposing partially written final files.
- `src/listen/store.rs` now applies deterministic required-file recovery to
  `project.json`, `session.json`, and `active-listener.lock.json`, preferring
  `.bak` before `.tmp`, logging successful recovery, and rewriting the primary
  path atomically.
- `src/listen/store.rs` keeps optional detail artifacts best-effort while
  returning clear unrecoverable errors for startup-critical metadata when no
  valid recovery snapshot exists.
- `src/listen/store.rs` now removes stale or corrupt orphaned locks, preserves
  blocking behavior for valid live locks, and uses file identity in
  `ListenerLockGuard::drop` so replacement locks are not deleted accidentally.
- `src/session_runtime.rs`, `src/listen/store.rs`, `src/listen/worker.rs`, and
  `tests/listen.rs` now cover torn-write preservation, required recovery
  success and failure, lock cleanup, live-lock blocking, replacement-lock
  safety, and built-in Claude canonical persistence across both running and
  failed listen-turn paths.
- `README.md`, `docs/agent-daemon.md`, `docs/listen-phased-execution-spec.md`,
  and `WORKFLOW.md` document the hardened persistence and recovery contract
  without changing schemas or CLI surface area.
